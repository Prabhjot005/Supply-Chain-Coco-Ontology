3. Expedite Workflow (Agent → Tool → MCP End-to-End)

The most complex multi-step workflow: user request triggers guardrails, DB writes, Jira ticket creation, and ticket linking.

sequenceDiagram
    actor User
    participant SCA as SUPPLY_CHAIN_AGENT
(Router)
    participant LA as LOGISTICS_AGENT
    participant TE as TRIGGER_EXPEDITE
(SP - Guardrails + DB)
    participant JIRA as ATLASSIAN_MCP
(Jira SCRUM)
    participant UAJ as UPDATE_ALERT_JIRA
(SP - Link Ticket)
    participant DB as Snowflake DB
(SHIPMENTS + ALERTS)

    User->>SCA: "Expedite shipment SH011"
    SCA->>LA: Route via agent_toolset LOGISTICS_TOOLS

    Note over LA: Step 1: Present details and confirm
    LA-->>User: "SH011 is delayed 5 days. Expedite as CRITICAL?"
    User-->>LA: "Yes, proceed"

    Note over LA: Step 2: Call SP with guardrails
    LA->>TE: TRIGGER_EXPEDITE('SHIPMENT','SH011','Delayed 5 days','CRITICAL')
    TE->>TE: Guardrail 1: Validate type = SHIPMENT
    TE->>DB: Check SH011 exists
    DB-->>TE: Found
    TE->>DB: Check 48h duplicate
    DB-->>TE: No duplicate
    TE->>DB: Check escalation cap (max 3)
    DB-->>TE: Count = 0
    TE->>DB: UPDATE SHIPMENTS SET priority='EXPEDITED'
    TE->>DB: INSERT INTO ALERTS (jira_ticket_id = NULL)
    TE-->>LA: "SUCCESS: Expedited SHIPMENT SH011. Alert ID: 34. NEXT: Create Jira ticket"

    Note over LA: Step 3: Create Jira ticket via MCP
    LA->>JIRA: create_issue(project=SCRUM, type=Task, summary="[EXPEDITE] SHIPMENT SH011")
    JIRA-->>LA: {key: "SCRUM-42", id: "10042"}

    Note over LA: Step 4: Link ticket back to Snowflake
    LA->>UAJ: UPDATE_ALERT_JIRA('SH011', 'SCRUM-42')
    UAJ->>DB: UPDATE ALERTS SET jira_ticket_id='SCRUM-42'
    UAJ->>DB: UPDATE SHIPMENTS SET jira_ticket_id='SCRUM-42'
    UAJ-->>LA: "SUCCESS: Linked Jira ticket SCRUM-42 to SH011"

    Note over LA: Step 5: Confirm to user
    LA-->>User: "Expedited SH011 as CRITICAL. Jira ticket SCRUM-42 created and linked."

5. Purchase Order Workflow (Procurement Agent)

sequenceDiagram
    actor User
    participant SCA as SUPPLY_CHAIN_AGENT
    participant PA as PROCUREMENT_AGENT
    participant GS as GENERATE_SCORECARD
(UDF read-only)
    participant CPO as CREATE_PURCHASE_ORDER
(SP write)
    participant JIRA as ATLASSIAN_MCP
    participant DB as Snowflake DB

    User->>SCA: "I need to reorder P100 for Chicago plant"
    SCA->>PA: Route via PROCUREMENT_TOOLS

    Note over PA: Uses reorder_advisor skill
    PA->>DB: Query DT_INVENTORY_POSITION for P100 at PL01
    DB-->>PA: on_hand=80, reorder_point=300, DOI=6 days

    PA->>GS: GENERATE_SCORECARD('S01')
    GS-->>PA: {composite: 8.2, otd: 9.1, quality: 8.5, cost: 7.0}
    PA->>GS: GENERATE_SCORECARD('S03')
    GS-->>PA: {composite: 8.8, otd: 9.5, quality: 9.0, cost: 7.8}

    Note over PA: Uses cost_analyzer skill
    PA->>DB: Query DT_LANDED_COST for P100 by supplier
    DB-->>PA: S01: $12.50/unit, S03: $12.80/unit

    PA-->>User: "Recommend: 500 units P100 from S03 (score 8.8, $12.80/unit) to PL01. Confirm?"
    User-->>PA: "Yes"

    PA->>CPO: CREATE_PURCHASE_ORDER('P100','S03','PL01',500,'Low stock reorder')
    CPO->>DB: Validate P100, S03 exist
    CPO->>DB: INSERT INTO PURCHASE_ORDERS
    CPO-->>PA: "SUCCESS: PO-0015 created"

    PA->>JIRA: create_issue(project=SCRUM, summary="[PO] P100 from S03 - Qty 500")
    JIRA-->>PA: {key: "SCRUM-43"}

    PA-->>User: "PO-0015 created. Jira SCRUM-43 for tracking."

    style BASE fill:#1e3a5f,stroke:#29b5e8,color:#e2e8f0
    style DT fill:#14532d,stroke:#22c55e,color:#e2e8f0
    style STR fill:#3b0764,stroke:#a855f7,color:#e2e8f0
    style TSK fill:#3b0764,stroke:#a855f7,color:#e2e8f0

Design decision: CURRENT_DATE() blocks INCREMENTAL refresh on DTs. Solution: the DT stores raw fulfillment data (no date functions), and the view computes live risk scores at query time. The stream watches the DT for changes, and the triggered task reads the view for up-to-date risk levels.
